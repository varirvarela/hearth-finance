Foundation Design Principles
⚡
Automation First
Rules (181 AutoCat patterns) and AI should categorize the vast majority of transactions without user input. Manual work is the exception, not the norm. Every manual action should ask "can we automate this next time?"
⚠️
Surface Deviations
Don't make the user hunt for problems. Overspend, unusual patterns, and missed goals must be visible on first glance — not buried in tables. Green = good, amber = watch it, red = act now.
🎯
Monthly & Annual Goals
Budget tracking is dual-mode. Monthly categories (groceries, restaurants) are measured against a monthly target. Annual categories (travel, home repairs, insurance) are measured YTD vs the full-year budget. The UI must distinguish these clearly.
📱
Mobile-First, Desktop-Capable
The primary experience is a phone: quick review and fast triage on the go. Desktop unlocks deeper analysis with more screen real estate. One codebase, adaptive layouts.

UX Pattern · Pace Indicator
The Pace Tick
The thin vertical bar on each progress track marks the expected spend at today's date. Day 14 of 31 = 45% mark. A filled bar extending past the tick = over pace (bad for expenses). A filled bar stopping before the tick = under pace (good). Fixed expenses skip the tick — they're binary (paid / not paid).
Critical · Data Model
Annual Categories Excluded from Dashboard
Categories tagged isAnnual (Travel, Casa Fijo Anual, Seguros, etc.) do not appear in the monthly progress bars — they'd be falsely "under budget" every non-event month. They live in the Annual view on Screen 3.
UX · Alert Priority
Alert Banner Logic
Banner triggers when: (1) any category exceeds 100% of monthly budget, (2) any category is on pace to exceed by >15%, or (3) unreviewed transaction count > 0. Tapping navigates directly to the problem — not a generic list.
Future
Trend Sparkline
Below the spending bars, a 12-month SVG line chart showing total spend vs budget over the year provides longitudinal context. Already implemented in v0.6.0 — this brief proposes moving it to a collapsible section to reduce initial scroll depth.

UX · Toggle
Monthly ↔ Annual Toggle
The toggle lives inside the green header bar — same green background as the month navigation. Switching to Annual changes the context from "August 2026" to "2026 Annual" and updates all bars to YTD vs annualized targets. The pace tick shifts from 45% (day 14/31) to 67% (month 8/12).
Data · Annualization
How Monthly Categories Are Annualized
Annual target = monthly budget × 12. YTD actual = sum of all transactions Jan–Aug in that category. This gives a true apples-to-apples comparison on the annual scale. Categories tagged isAnnual use their explicit annual budget — no multiplication needed.
UX · Travel Pattern
Intentionally Under-Pace = OK
Travel at 13% of annual budget by August isn't alarming — it may be planned for December. The annual view should let the user add a note like "planned for Q4" to suppress false alerts. For now, the muted color treatment (grey text) signals awareness without urgency.

UX · Visual State
Three Categorization States
Each row communicates its state through background color and a dot badge: clean white = fully categorized; amber background + amber dot = AI suggestion waiting for confirmation; red background + red dot = fully uncategorized. No icons needed beyond color.
UX · Rule Creation
Inline Rule Prompt
After any category change (confirm or manual pick), a prompt appears immediately below the row offering to create a permanent rule. Dismisses automatically after 2 seconds or on Skip. No navigation to Settings required — the whole flow stays in context.
Data · Source Filter
Source Filter Values
Five source buckets: ai (AI Worker), rule (AutoCat engine), manual (user-set), import (Tiller CSV — normalized from "tiller"), plaid (live bank sync). Useful for auditing: e.g. show only rule to verify AutoCat is firing correctly.

Data Model · Monthly vs Annual
Why Two Separate Views?
Categories with isAnnual: true behave differently: Travel might be $0 for 10 months then $11,500 in December. Showing that on a monthly bar chart would constantly show "under budget" as a false positive. Annual view measures YTD spend vs the full-year budget, with the pace tick at currentMonth / 12.
Future · Drill-Down
Tap Row → Filtered Transactions
Tapping any budget row should deep-link to the transaction list pre-filtered for that category and period (current month for monthly view, YTD for annual). This is the fastest way to investigate an over-budget number without rebuilding filters manually.
UX · Color Scale
Progress Bar Color Thresholds
🟢 Green fill = at or under pace (spend% ≤ pace% + 10%)
🟡 Amber fill = over pace but under 100% budget
🔴 Red fill = over 100% of budget
Row amounts use the same color so the number and bar always agree at a glance.

UX · Dark Hero
Balance Sheet in 3 Numbers
The dark header contrasts the list below to signal "this is a financial snapshot." Three numbers: assets (green), liabilities (red), net worth (white). A user can read their financial position in under 2 seconds before scrolling to account details.
Data · Sync Status
Freshness Color Coding
🟢 Green dot = synced within last 4h
🟡 Amber dot = 4–48h since last sync (stale)
🔴 Red dot = sync error or >48h
⚪ Grey dot = manual entry, no sync

The stale state should also offer an inline "Reconnect" nudge on the account row.
Future · Account Reports
Tap Account → Detail View
Tapping an account should show: 30/90-day balance sparkline, top 5 merchants on this card this month, total spend for current period, and a button to filter transactions by this account. This makes it easy to understand "what did I put on my AmEx this month?"
Future · Net Worth Trend
Monthly Net Worth Chart
A 12-month line chart showing net worth over time (assets vs liabilities stacked area) would turn the Accounts tab from a snapshot into a progress tracker. This requires monthly balance snapshots stored in RTDB — not yet implemented.

UX · Not a Spreadsheet
Rule Cards vs Data Rows
Each rule displays as a semantic card: when [field] [op] "[pattern]" → category. This is instantly readable vs a dense table. The match count ("47 matches") shows which rules are doing the heavy lifting — high-match rules should be reviewed carefully before editing or deleting.
UX · Grouped by Outcome
Category-Centric View
Rules are organized by their target category, not by creation date or priority. When you ask "why is Whole Foods going to Super?", you open the Super group and see all 22 rules at a glance. Adding a rule from within a category group pre-fills the outcome field.
UX · Preview
Live Preview Before Saving
The rule form shows a natural-language preview of the rule as you fill in the fields. This prevents mistakes like saving "description contains 'amazon'" when you meant "merchant name contains 'amazon'" — different match results in practice.
Data · Priority Tiers
Rule Priority System
10 — Transfers (exact match, checked first)
20 — Income & business charges
30 — Known merchants (specific stores)
40 — Named patterns (partial merchant)
50 — Broad patterns (generic terms)

"Auto" defaults to 30. Lower number = higher priority.

Future State · Insight Types
Four Insight Tiers (Priority Order)
🔴 Budget violations — already over, act now.
🟡 Pace warnings — on track to exceed, watch it.
🟣 Anomalies — unusual vs your 3-month average.
🔵 Optimizations — subscriptions, duplicates, waste.
🟢 Good news — always include; positive feedback matters.

Each card must have an action link or it becomes noise.
Data Requirements
What Each Type Needs
• Pace warnings: current spend + budget + day-of-month. Already available.
• Anomalies: rolling 3-month category average. Already computed in RTDB.
• Subscription detection: recurring merchant + ±$1 amount tolerance + monthly interval. New logic.
• Annual underuse: YTD vs pro-rated annual budget. Available from Budget tab.
UX · Navigation
Insights Replaces a Nav Slot
When Insights is ready, the bottom nav tab "Settings" should move to a gear icon inside each page's header, freeing the fifth slot for 💡 Insights. Settings is an infrequent destination; Insights should be checked regularly.

Automation is not in the nav but is reachable via "Manage categorization rules →" in the Accounts settings section and from the Insights footer.

Screen 2b

Dashboard → Category Drill-Down

Interaction: Tapping any category row in the Dashboard's "Spend vs Budget" section navigates to Transactions pre-filtered to that category and month. The filter state is passed via sessionStorage so it survives the tab switch.
Goal: Make the Dashboard actionable — not just a read-only summary, but a launch point for triage. If "Salidas" is 87% of budget at pace day 12, one tap shows exactly which restaurants and outings drove it.
